## 4. 内容管理操作

### 首页与轮播

按前台实际区域切换：轮播、产品展示、咨询横幅、客户案例、品牌优势、技术实力、公司介绍、新闻，以及公共页头、导航和页尾。电脑与手机版布局可分别维护。

轮播卡片显示图片与推荐尺寸，支持选择或上传图片、修改点击目标、左右移动调整顺序。保留现有轮播槽位数量；目前没有任意增加或删除轮播槽位的独立操作。

### 产品、新闻与案例

列表支持标题搜索、中文栏目筛选和上线、待发布、下架状态筛选。新增内容先选择所属栏目，再选择空白正文或复制已有内容。新内容先是草稿；发布后加入所选栏目，并生成两端详情页。

可编辑标题、摘要、封面和富文本正文。正文及主要元数据同步到电脑和手机版。固定页面的图片、链接及文案可按设备和板块编辑。已经存在的内容分类由模板确定，目前没有完整的分类移动界面。

### 草稿、预览、发布与恢复

编辑时实时预览不写入数据库。点击预览中的编辑区域可定位对应字段。保存草稿不会更改前台；点击“发布到前台”才更新访问内容。下架也需要发布，发布后隐藏入口并使详情页不可访问。

已发布版本保留历史，可恢复为新草稿，再检查预览并重新发布。并发编辑采用版本检查，发现草稿已被其他操作更新时会要求重新打开，避免覆盖。

### 图片素材

支持 PNG、JPG、GIF、WebP，单张不超过 8MB，一次最多选择 30 张。支持批量选择、拖拽、进度、失败重试、重复内容复用、图片名称和用途管理。

图片用途包括轮播、产品、新闻、案例、正文插图、标志或二维码、其他素材。选择素材后点击“应用图片”，再保存并发布页面。上传文件本身不会自动替换前台图片。原站素材可选择，上传素材可重命名和改变用途。并非所有 WebP 变体都能解析尺寸；未知尺寸不影响图片正常使用。

### 留言与网站设置

留言支持搜索、处理状态、跟进备注与 CSV 导出。网站设置统一维护公司名、电话、邮箱、地址、微信号、页头标志和二维码；设置同样区分草稿与发布。

Linux 独立后台右上角支持修改密码和退出。密码修改会使之前的登录会话失效。

### 接手阅读提示

先读 `docs/给接手AI的部署说明.txt`，再读本文、`deploy/README.md`、`docs/CHANGELOG.md` 和 `AGENTS.md`。接手时实时核验服务器状态、分支版本和持久数据，保留已有站点，不使用历史 ZIP 替代最新源码。

## 5. 技术结构

| 目录或文件 | 作用 |
| --- | --- |
| `source/desktop/`、`source/mobile/` | 原始 HTML、CSS、JS 和图片镜像 |
| `source/snapshot-manifest.json` | 页面与资源清单 |
| `branding/` | 覆盖原资源路径的品牌替换图片 |
| `assets/` | 前台补充脚本、样式、東悍标志 |
| `admin/` | 管理界面与图片管理组件 |
| `worker/index.js` | 页面路由、上传路径及咨询接口 |
| `worker/cms.js` | CMS、内容清理、草稿、发布、历史与媒体逻辑 |
| `server/runtime.mjs` | Node HTTP 服务、SQLite、文件存储、独立登录和入口转换 |
| `server/mount.mjs`、`assets/site-path.js` | 前缀、后台别名、HTML/CSS/资源/跳转转换 |
| `server/setup.mjs` | 首次管理员初始化 |
| `server/backup.mjs` | SQLite 一致性备份 |
| `db/schema.ts`、`drizzle/` | 数据库模型与有序迁移 |
| `scripts/build.py`、`scripts/cms_build.py` | 镜像构建、品牌替换、路由映射与 CMS 标注 |
| `worker/seo.js` | 规范网址、元数据、动态地图、抓取规则与选型指南 |
| `deploy/register-baota-site.py`、`deploy/install-baota.sh` | 宝塔站点登记、首次迁移、失败恢复 |
| `deploy/install.sh` | 旧独立 Host 首次安装及失败恢复 |
| `deploy/update.sh` | 保留既有路由、账号和数据的代码升级 |
| `AGENTS.md`、`docs/CHANGELOG.md` | 修改时的文档与 GitHub 同步约定、验证记录 |
| `.openai/hosting.json` | 原托管网站身份与 Cloudflare 存储绑定 |

两种运行方式共享业务代码：托管版使用 Cloudflare Worker、D1、R2 和平台账号身份；Linux 独立版使用 Node 24、SQLite、本地文件存储及独立登录。Linux 独立部署应启动 `server/runtime.mjs`，无须把 Worker 直接交给 Node 执行，也不需要连接原托管数据库。

运行服务会把客户端提供的账号身份头去掉，再按本机签名会话授权；开发用 `CMS_LOCAL_DEV=1` 不应配置到 Linux 生产服务。HTML 使用 sanitize-html 清理，SQLite 查询使用绑定参数。

## 7. 源码构建、安装与升级

构建使用 Node 22.13+、npm 与 Python 3；Linux 独立服务端必须使用 Node 24。`build` 和 `check` 明确调用 `python3`，适配没有 `python` 别名的环境。

```bash
npm ci
npm run build
npm run check
node scripts/server-qa.mjs
node scripts/mount-qa.mjs
node scripts/uguest-qa.mjs
npm run test:seo
```

构建得到 `dist/client/`；Linux 独立服务端从 `worker/`、`server/` 加载业务代码。生产依赖、迁移及页面资源必须一起发布，不能只复制 HTML。

在隔离目录测试当前入口：

```bash
DATA_ROOT=./.server-data node server/setup.mjs
PORT=8010 DATA_ROOT=./.server-data PUBLIC_URL=http://127.0.0.1:8010 BASE_PATH=/donghan ADMIN_PATH=/uguest node server/runtime.mjs
```

访问 `http://127.0.0.1:8010/donghan/` 和 `/donghan/uguest/`。不配置前缀时，默认根路径及 `/admin/` 仍用于原有开发验收与独立 Host 安装；当前生产服务明确覆盖为上述配置。

### 当前服务器升级

在独立源码目录获取新版本并完成构建与检查。打包至少包含 `dist/`、`worker/`、`server/`、`drizzle/`、`node_modules/`、`package.json` 和 `deploy/`。生产依赖应为目标 Linux 架构，或仅包含本项目的纯 JavaScript 生产依赖。

在新包目录执行：

```bash
sudo bash deploy/update.sh
```

该脚本要求已经存在的网站安装；备份 SQLite 和原服务配置，创建新发布目录，切换 `current`，重启并检查健康状态，失败时恢复旧发布。它保留原 `PUBLIC_URL`、`BASE_PATH`、`ADMIN_PATH`、nginx、上传图片和账号配置。不得从运行中的 `current` 目录直接执行升级。

### 宝塔首次迁移安装

先安装宝塔官方 Nginx，核对目标系统及架构，准备 Node 24.21.0 和完整构建包。对旧站创建 SQLite 一致性备份，并通过 SSH 传输管理员配置、数据库与上传目录，不能提交至 GitHub。

```bash
cd /www/server/panel
/www/server/panel/pyenv/bin/python3 /path/to/package/deploy/register-baota-site.py --host 43.128.69.6
cd /path/to/package
bash deploy/install-baota.sh /private/migration-snapshot 43.128.69.6 8010
```

脚本只接受已确认的新站点及完整迁移快照，备份宝塔初始配置，建立专用用户和 systemd 服务，验证后再启用代理。失败恢复原站点配置，保留私有数据和发布以便恢复。已安装网站使用 update.sh，不重复执行首次迁移。

### 全新独立 Host 安装

`deploy/install.sh <域名> <回环端口>` 适用于已准备 nginx 和 Node 24 的全新独立 Host 安装。默认站点路径是根目录。它不会自动把现有默认 IP 站点转换成 `/donghan/` 模式。当前生产网站升级应使用 `update.sh`，不能用默认安装脚本覆盖已部署配置。

数据库变更只能追加新迁移；不得改写已应用迁移。任何升级都不得删除 `/var/lib/donghan`。

## 10. 维护与恢复

```bash
sudo systemctl status donghan --no-pager
sudo systemctl is-enabled donghan
sudo /www/server/nginx/sbin/nginx -t
curl -fsS http://127.0.0.1:8010/donghan/healthz
sudo journalctl -u donghan -n 80 --no-pager
cat /var/www/donghan/current/REVISION
```

修改服务环境后执行 `systemctl daemon-reload` 和 `systemctl restart donghan`。变更 HTTPS 时同步更新 `PUBLIC_URL` 为真实 HTTPS 源。
