# 東悍网站操作手册

更新日期：2026-10-15。适用主站：http://43.128.69.6/donghan/ 。操作按当前已有功能编写。

- 电脑前台：http://43.128.69.6/donghan/
- 手机前台：http://43.128.69.6/donghan/mobile/
- 管理后台：http://43.128.69.6/donghan/uguest/

旧服务器 159.75.67.132 上的東悍项目已于 2026-10-15 清理，旧地址不再使用。后续编辑、留言处理和维护均使用新 IP；旧服务器的其它网站仍保留。

## 2. 编辑现有内容

1. 在后台选择产品、新闻、案例或页面，按中文栏目、标题或状态找到目标。
2. 打开编辑器，修改标题、摘要、封面和正文。固定页面可按电脑/手机及页面区域选择内容；点击预览区域可定位对应字段。
3. 先检查电脑和手机版预览。预览不写入数据库。
4. 点击“保存草稿”。草稿不会改变前台。
5. 确认后点击“发布到前台”，再打开对应前台链接检查标题、图片、文字和内部链接。

遇到“内容已被更新”等版本冲突提示，重新打开内容确认最新版本，避免覆盖其他人的修改。正文与主要元数据会同步两端，部分布局区域仍需分别维护。

## 3. 首页、轮播和图片

首页可按轮播、产品展示、咨询横幅、案例、品牌优势、技术实力、公司介绍、新闻及公共页头页尾选择区域。

更换轮播：选择对应卡片，按推荐尺寸准备图片，选择或上传图片，确认点击目标，必要时调整已有卡片顺序，然后保存草稿、预览、发布。当前保留既有轮播槽位数量，不支持任意新增或删除槽位。

图片支持 PNG、JPG、GIF、WebP，单张不超过 8MB，一次最多选择 30 张。上传后选中素材，点击“应用图片”，再保存并发布相应页面。只上传文件不会自动替换前台。上传图片可维护名称和用途，重复内容可复用。

## 4. 新增、下架和恢复

新增产品、新闻或案例时，先选择所属栏目及空白/复制模板，填写内容并预览，再保存和发布。发布后会生成电脑与手机详情页并加入对应栏目。

下架内容也需要发布，发布后入口隐藏、详情返回 404，网站地图移除该内容。重新上线时取消下架并发布。

恢复旧版本：打开历史版本，选择恢复为草稿，核对预览后重新发布。恢复草稿不会立即改动前台。原始快照也可以恢复为草稿，操作前先确认它不会覆盖需要保留的新内容。当前没有完整的分类移动界面。

## 5. 网站设置和咨询留言

网站设置可修改公司名称、电话、邮箱、地址、微信号、标志及二维码。先保存草稿，再“发布设置”，随后检查电脑、手机的页头页尾和联系方式。页面中的独立文案需要到对应页面检查和编辑。

公司、联系资料、资质与历史案例来自原镜像，须由所有者核实，不应编造认证、评分、售价或节能承诺。

咨询留言支持搜索、处理状态、跟进备注及 CSV 导出。导出文件包含客户信息，应私下保存，不进入 GitHub、公开日志或操作截图。页面的本地浏览次数不等于全站访客数；目前没有电话、微信或按钮点击埋点。

## 6. 每次更新必须执行的流程

适用于本项目的源码、文案、图片、配置、路由、部署和纯文档更新。

1. 核对 GitHub main 与当前服务器版本，读取 AGENTS.md，确认目标是 43.128.69.6；识别要保护的持久数据。
2. 完成变更及与其相关的必要验证。先把可恢复备份或旧发布位置记清楚；生产环境不写入验收内容。
3. 更新 docs/CHANGELOG.md：写明时间、原因、变更、影响范围、验证、部署结果和恢复信息。
4. 更新 docs/项目文档.md，并重新生成、逐页检查 docs/项目文档.pdf。根据变化更新 README、部署和交接说明。
5. 每次核对并更新本操作手册；操作没有变化时也记录“已核对，步骤不变”，不虚构修改。
6. 将本次相关源码、资源、配置模板、日志和文档同步到 GitHub，并部署到主服务器的可恢复新发布。不能只更新本地或只推 GitHub。
7. 核对线上功能、文件 SHA256 和 current/REVISION 与 GitHub 提交一致。向服务器 /var/www/donghan/deployment-log.jsonl 追加脱敏部署记录，列出提交、发布、文件、验证和回退位置。
8. 向所有者报告结果与实际访问地址；任何一步失败都明确说明，不能说成全部已同步。

后台发布的内容已保存在服务器数据库中，应核对实际页面并补齐变更记录及相关说明。数据库、客户留言、管理员配置和上传原始私有数据不提交到 GitHub；不得用旧空库覆盖服务器。用户手动编辑后台不会自动触发本手册流程，当前没有安装后台文档生成器或自动 GitHub 同步服务。

## 7. 维护人员的服务器操作

服务为 donghan.service，用户 donghan；持久数据 /var/lib/donghan，程序 /var/www/donghan/current。宝塔站点占位根目录 /www/wwwroot/donghan 不是完整源码。

```bash
sudo systemctl status donghan --no-pager
sudo systemctl is-enabled donghan
sudo /www/server/nginx/sbin/nginx -t
curl -fsS http://127.0.0.1:8010/donghan/healthz
cat /var/www/donghan/current/REVISION
sudo journalctl -u donghan -n 80 --no-pager
```

普通源码升级先在独立目录构建与验证，再执行该包的 deploy/update.sh；保留 PUBLIC_URL、BASE_PATH、ADMIN_PATH、nginx、账号及生产数据。纯文档更新可以使用相同的发布目录和原子切换办法，校验业务代码不变，无须重新执行无关业务测试。不要在 current 目录直接编辑或重新执行首次安装脚本。

宝塔代理为 /www/server/panel/vhost/nginx/43.128.69.6.conf。变更前先备份、检查语法，再按变更需要重载。8010 仅回环监听；当前网站使用 HTTP。

回退代码前确认旧发布和备份，切回已知版本并检查健康；数据库恢复必须评估后续真实数据，不自动回退已应用的迁移。详细部署与恢复见 deploy/README.md 和项目文档。

旧机退役恢复资料位于新服务器 /var/backups/donghan-retired-159.75.67.132-20261015/recovery.tar.gz，仅管理员私下访问。恢复前解压到私有隔离目录核对；不要覆盖当前生产库，不要整份覆盖共享 nginx 配置。恢复到旧机必须由所有者另行授权，并重新检查路由及其它网站。
